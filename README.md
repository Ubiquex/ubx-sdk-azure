# ubx-sdk-azure

Typed bindings for Azure (`[dynamic_provider_groups.azure_all]`,
ARM-Swagger-sourced via `ubx-provider-dynamic`), generated by
[ubx](https://github.com/ubiquex/ubiquex) (`ubx sdk gen`), for all three
SDK languages in one combined repo:

- [`sdk/go/`](sdk/go/) -- Go bindings, module `github.com/ubiquex/ubx-sdk-azure/sdk/go`
  (a subdirectory Go module, tagged `sdk/go/vX.Y.Z`)
- [`sdk/typescript/`](sdk/typescript/) -- TypeScript bindings, published to JSR as
  [`@ubx/sdk-azure`](https://jsr.io/@ubx/sdk-azure)
- [`sdk/python/`](sdk/python/) -- Python bindings, published to PyPI as
  [`ubx-sdk-azure`](https://pypi.org/project/ubx-sdk-azure/) (imported as
  `ubx.azure.*`, a real PEP 420 namespace package)

One package per Azure resource-provider domain (`compute/`, `storage/`,
`sql/`, ...), one file per resource type, in every language.

## v1.0.0: identity replacement, not just a version bump

Every version before `1.0.0` was generated from the `hashicorp/azurerm`
Terraform provider, and every generated path reflected that source name
(`azurerm/compute/...`, `ubx.azurerm.compute`) even though the repo and
package names were already `azure`. As of `1.0.0`, this repo is
generated from Azure's own real ARM Swagger specs across all 302 real
`[dynamic_providers.azure*]` entries (the original azure/compute entry
plus 301 `azure_<domain>` entries), the source `ubx` actually resolves
and applies changes against today -- every generated path now says
`azure/...`/`ubx.azure.*`, matching the repo/package identity for the
first time.

`azurerm_*` and `azure_*` are a permanent, structural namespace split,
not staleness -- verified zero real overlap by type name between the two.
Publishing more `azurerm_*` content would never have helped the current
`azure_*` corpus; this release replaces the identity entirely rather
than trying to reconcile two schemas that were never the same shape.
1095 real resource types across every Azure resource-provider domain
with a live ARM spec (was 1103 `azurerm_*` types before). Hence `1.0.0`,
not a minor bump -- this is a real identity replacement.

`[dynamic_provider_groups.azure_all]` (`ubiquex` commits `c55908c`/
`8062883`, ported to Azure's own 302-entry corpus) merges every member's
own real schema into one combined output -- the same mechanism
`ubx-sdk-google` uses for its own 162-member GCP corpus.

`VERSION` records a `merged-schema-sha256`: a SHA-256 of the combined,
deterministic post-enrichment IR (`ubx sdk gen --dump-ir`'s own
`schema.json` shape) covering all 302 members at once, plus the member
count and fetch date. There is no single upstream "Azure version" --
each of the 302 ARM specs pins its own dated API-version folder
independently (`stable/2026-04-01`, one date per family, never one
global version) -- so a single merged-content hash is the real, honest
equivalent of the content-hash scheme `ubx-sdk-aws`/`ubx-sdk-kubernetes`/
`ubx-sdk-datadog`/`ubx-sdk-github` already use for their own
no-discrete-release sources.

`.github/workflows/version-watch.yml` is removed (it polled the
Terraform Registry for a `hashicorp/azurerm` bump, which no longer
matches this repo's real source at all). A real 302-member content-hash
watch mechanism is separate follow-up work, not done in this PR.

Package identity (module path, JSR/PyPI names) is unchanged -- only
the generated content, its internal `azure` naming, and `VERSION`'s own
format changed.

Local sanity: `go build`/`go vet` clean against the regenerated
`sdk/go/` tree (1219 files, 302 real resource-provider packages).
TS/Python sanity (`deno check`, real module import) not run locally.

Depends on the shared runtime: [ubx-sdk-go](https://github.com/ubiquex/ubx-sdk-go) (Go),
[`jsr:@ubx/sdk`](https://jsr.io/@ubx/sdk) (TypeScript),
[`ubx-sdk`](https://pypi.org/project/ubx-sdk/) (Python, imported as `ubx_sdk`).
